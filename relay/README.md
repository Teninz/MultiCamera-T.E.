# MultiCamera T.E. — свой сервер

Сервер соединяет Windows-приёмник и до пяти смартфонов через исходящие WebSocket-соединения. ПК и телефоны могут находиться в разных сетях. Проброс порта на домашнем роутере не требуется. Публичный сервер, домен и размещение предоставляет владелец установки; общего сервера MultiCamera T.E. в комплекте нет.

## Развёртывание

Нужны сервер с публичным адресом, домен, направленный на него, и Docker Compose. Для приведённого Caddy-конфига сервер должен принимать TCP 80 и 443.

1. Скопируйте `Caddyfile.example` в `Caddyfile`; замените `camera.example.com` своим доменом.
2. Скопируйте `.env.example` в `.env`; задайте длинный случайный `MULTICAMERA_HOST_KEY`. Например, значение можно получить командой `openssl rand -hex 32`. `.env` содержит ваш ключ; не добавляйте его в Git.
3. Запустите `docker compose up -d --build` из этой папки. Caddy обслуживает HTTPS; внутренний порт 8080 не публикуется на хост.
4. В Windows: **Настройки → Адрес сервера** — `wss://ваш-домен`; в поле ключа укажите `MULTICAMERA_HOST_KEY`, включите интернет-подключения и сохраните.
5. Откройте подключение нужного смартфона и выберите **Интернет / свой сервер**. Считайте правый QR Android-приложением. Повторите для остальных устройств, используя отдельную карточку для каждого.

Для собственного обратного прокси направьте WebSocket-маршруты `/v1/host/...` и `/v1/phone/...` на `server.py`. Если прокси размещает сервис под префиксом, он должен убрать этот префикс перед передачей запроса серверу. Адрес с тем же префиксом укажите в Windows-приложении. Сертификат должен быть доверенным для Android и Windows; обход проверки сертификатов не предусмотрен.

## Локальная разработка

Установите `requirements.txt` в отдельное окружение и запустите `python server.py`. По умолчанию слушается `127.0.0.1:8080`. Переменные `MULTICAMERA_BIND`, `MULTICAMERA_PORT` и `MULTICAMERA_HOST_KEY` переопределяют параметры. Нативные клиенты принимают только WSS, поэтому для подключения устройств перед этим HTTP-процессом требуется HTTPS-прокси.

## Данные и ограничения

Сервер пересылает бинарные сообщения и не записывает видео или звук. Пакеты дополнительно зашифрованы между смартфоном и ПК протоколом OLC1/AES-GCM. Ключ камеры находится во фрагменте QR и не входит в адрес WebSocket, передаваемый серверу. Серверу видны сетевые метаданные и номера каналов. Ключ доступа к серверу и индивидуальные ключи камер — разные значения.

На слот допускается один приёмник и один смартфон. Дубликат не вытесняет действующее подключение. При разрыве закрываются обе стороны, после чего Windows-приёмник повторяет подключение. Используются ограниченные очереди и WebSocket keepalive.

Видеотрафик всех устройств проходит через сервер: его пропускная способность и расстояние влияют на задержку. Реальная передача через внешний VPS в этом выпуске ещё не измерялась. Автоматическая проверка включает пять потоков через локальный relay, настоящий Android WSS-клиент, keepalive и отклонение неверных сертификатов и имён узлов; положительная проверка Windows-туннеля использует отдельную локальную WS-фикстуру, не меняя строгий WSS в продукте.
