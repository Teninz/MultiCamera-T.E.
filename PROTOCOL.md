# OLC1, версия протокола 1

Один поток TCP, порт по умолчанию 34871. Допускается один отправитель. Начиная с приложения/плагина 0.3 доступны диагностические и аудиопакеты. Все целые числа — big endian, кроме PCM-сэмплов little endian.

Сопряжение: URI `obslan://<private-ipv4>:<port>#<32 lowercase hex characters>`. Ключ — 16 случайных байт. Он передаётся пользователю через QR на экране компьютера; сетевой HTTP endpoint с ним доступен только с loopback и проверяет Host.

1. Клиент отправляет ASCII `OLC1` и 16 случайных байт client nonce.
2. Сервер отправляет 16 случайных байт server nonce.
3. Ключ сеанса: `SHA256(pairing_key_bytes || client_nonce || server_nonce)`.
4. Запись клиента: длина uint32, sequence uint64, ciphertext, 16-байтный GCM tag. Длина включает sequence, ciphertext и tag. Верхняя граница — 4 MiB.
5. AES-GCM nonce: ASCII `OLC`, байт направления (1 клиент → сервер, 2 сервер → клиент), sequence uint64. AAD отсутствует. Номера должны строго совпадать с ожидаемым порядком.
6. Запись клиента с sequence 0 содержит plaintext `00 48 45 4c 4c 4f` (ноль и HELLO).
7. Сервер отвечает 18 байтами: зашифрованным ASCII OK и GCM tag, направление 2, sequence 0.
8. Записи клиента начинаются с sequence 1. Общий заголовок plaintext: type uint8, clockwise rotation uint16 (0/90/180/270), presentation time uint64 в микросекундах. Видео и аудио используют одну атомарную последовательность записей.

| type | Тело после 11-байтного заголовка |
| --- | --- |
| 1 | Параметры H.264 Annex B, SPS/PPS |
| 2 | H.264 Annex B видеопакет |
| 3 | Диагностика UTF-8, не более 2048 байт, без ключа сопряжения |
| 4 | sample_rate uint32 BE, channels uint8 (1/2), затем PCM16 LE interleaved |

Для аудио поддерживаются 48000, 44100 и 16000 Гц; один пакет не длиннее 200 мс. Android отправляет mono, примерно 20 мс. Выключение микрофона прекращает аудиопакеты и освобождает AudioRecord; отдельный сетевой сигнал mute не нужен. Неподдерживаемый тип записи закрывает соединение, поэтому для звука нужны обе стороны версии 0.3 или новее.

Параметры SPS/PPS могут приходить отдельно. Приёмник добавляет их перед следующим видеопакетом. FFmpeg декодирует 8-битный YUV420p; планарный поворот выполняется до передачи в OBS. PTS видео и аудио относятся к Android BOOTTIME и отображаются на монотонные часы OBS с единым смещением для сеанса. Проверяется предел времени и пересоздаётся смещение при скачке более 5 секунд. Точная задержка и рассинхронизация на телефоне ещё не измерены. Допускается 8-битный YUV420 до 8192 по стороне и 33 177 600 пикселей (8K); это ограничение декодера, а не обещание производительности.

Конфигурационные/видеопакеты, превышающие ограничения, неверные sequence и ошибки аутентификации закрывают соединение. При разрыве Android повторяет полный сеанс с новыми nonce.

Проверка обновлений использует отдельное HTTPS-соединение к публичному GitHub API и не участвует в этом протоколе.
