# Проверка 0.4.1 — MultiCamera T.E.

12 ноября 2026, Windows 11 x64, OBS 33.0.1.

- Пять одновременных Java Wire клиентов: реальный H.264, независимые повороты и PCM/mute, AES-GCM, отклонение второго клиента с занятым ключом.
- Пять Windows virtual cameras: перечисление через Media Foundation и по 10 живых NV12 кадров через FrameServer у каждой.
- Пять настоящих источников libobs: 170+ правильных кадров у каждого, 21 120 PCM-сэмплов, ненулевой звук; корректное закрытие после удаления тестового фильтра.
- WSS: Android strict TLS, неверный hostname/сертификат отвергаются. Windows production TLS отвергает недоверенный сертификат с 12175. Положительный тест host relay использует только отдельную scratch-копию с loopback WS; в продукте ослабления TLS нет.
- Пользователь подтвердил передачу изображения реального смартфона через USB-модем Android. Пять физических смартфонов одновременно пока не проверялись.
- Новый WebView2 интерфейс: обе темы, живые превью пяти потоков, LAN/USB QR, настройки. Независимый агент принял главный экран, настройки и подключение; замечания по читаемости и доступным именам исправлены.
- Установщик: явная ведомость 29 файлов, извлечение и SHA-256 каждого файла. Требуется Microsoft Edge WebView2 Runtime (на тестовом ПК установлен).

Ограничения: нет проверки Zoom/Telegram по каждой версии; длительный прогон пяти физических телефонов, реальный внешний VPS и жесты затемнения на физическом телефоне ещё не подтверждены. Предыдущая установленная версия может требовать запуска нового установщика и подтверждения UAC пользователем. Публичный выпуск отмечается отдельно после загрузки всех артефактов.

# Проверка версии 0.3.1

- Снимок пользователя подтвердил неверное превью в 0.3.0 при нормальном видео OBS. Причина в коде: матрица повторно учитывала SENSOR_ORIENTATION поверх системного Camera2 producer transform. Прежние тесты проверяли только матрицу raw-буфера и не учитывали этот этап Android.
- Теперь тестируется системно ориентированный буфер: 384 комбинации размеров, ориентации сенсора, поворота дисплея и заполнения/вписывания. Проверяются равный масштаб по осям, центрирование и компенсация только поворота дисплея. Дополнительно проходят прежние 192 проверки аффинной геометрии.
- Производственный CameraPolicy проверен на отсутствие стабилизации, EIS, preview EIS, OIS, приоритет при 60 FPS и отклонение 60 FPS при диапазонах камеры до 30.
- Проверены ответы камеры в модели обратной связи: ожидание запуска, подтверждение EIS, переход к OIS после OFF, недоступность в выбранном режиме и отсутствие подтверждающих метаданных. Это проверка логики, не измерение стабилизации на телефоне.
- APK подписывается сохранённым ключом, проверка v2/v3 обязательна при сборке. Внешних Android-устройств через ADB на момент проверки нет.

После установки 0.3.1 пользователь подтвердил: превью исправилось, стабилизация и выбор 60 FPS доступны на его смартфоне. Длительная работа, точная фактическая частота и эффективность стабилизации инструментально не измерялись. Другие модели, включая Redmi Note 9S, отдельно не подтверждены. Стабилизация зависит от выбранной камеры и режима.

# Проверка версии 0.3.0

Среда: Windows, OBS Studio 33.0.1, RTX 3080; Android SDK 35, JDK 17. Дата: 11 ноября 2026 года.

## Подтверждено

- Производственные DLL и APK собираются; APK проходит apksigner verify v2/v3. Ключ подписи сохранён от прежних выпусков.
- Настоящий libobs / Direct3D 11 принимает из производственного Java Wire тестовый H.264 и PCM16 48 кГц. После поворота 90° квадранты имеют ожидаемые уровни яркости 41 / 77 / 235 / 149. Последний прогон: 143 корректных кадра, 75 840 аудиосэмплов, 79 пакетов с ненулевым сигналом.
- Проверены перемежение видео/звука из разных потоков Java, выключение аудиопакетов без остановки видео, повторное подключение, отдельные SPS/PPS, неверный ключ, диагностика Android, запрет выдачи ключа по LAN и проверка Host.
- Геометрия превью проверена для 192 комбинаций разрешения, размера окна, 0/90/180/270°, зеркала и заполнения/вписывания: одинаковый масштаб по осям, центрирование и корректные границы.
- Android-политика обновлений проверена отдельно: сравнение версий, точный репозиторий/имя APK, HTTPS и разрешённые CDN, формат SHA-256, предельный размер. Проверки выполняют реальные классы ReleasePolicy / ReleaseDownload.
- Реальный EXE через --extract-to распаковал 8 файлов; SHA-256 каждого совпал с инвентарём сборки. Подсистема Windows GUI и содержимое ZIP проверены. Сертификаты подписи APK 0.2 и 0.3 имеют одинаковый SHA-256.
- При первом запуске выявлено обращение к Qt из графического потока OBS. Получение native handle перенесено в OBS_TASK_UI; исправленная сборка запущена в обычном OBS, окно с двумя QR открылось автоматически, источник появился в микшере. Ключ остаётся в памяти окна и не публикуется.

## Границы проверки

Пользователь подтвердил видеопоток старого APK на Realme GT ME. Новые Camera2/MediaCodec режимы, интерфейс Android, поворот и реальный микрофон в 0.3.0 требуют проверки на смартфоне. ADB-устройств на ПК во время разработки не было. Ошибка Redmi Note 9S / Android 12 без журнала устройства не установлена; добавлены подбор кодировщика, упрощённая конфигурация, резерв YUV и диагностика. Исправление конкретной модели пока не подтверждено.

Java-тест проверяет фактический HTTPS-код скачивания и SHA-256, но не заменяет проверку Android-диалогов, выдачи разрешения установки и системного установщика на телефоне. Сам APK не устанавливался автоматически на устройство.

Точная задержка/синхронизация звука, длительная трансляция и перегруженный Wi-Fi не измерены. 4K/60/8K в списке определяются сообщаемыми возможностями, а не обещанием производительности.

Установщик поддерживает резервную копию и запрос закрытия OBS. Проверка реальной распаковки выполняется через --extract-to; административное повышение и установка на чистой Windows не проверены. Доступ Computer Use к окну нашего EXE не был предоставлен инструментом; это не считается прохождением мастера установки.
